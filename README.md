## 三、怎么学才有效（重要）

1. **先跑起来看结果**：`dotnet run`，看一眼输出，和你预期的一样吗？
2. **改参数再跑**：把温度改成 95、把报警上限改成 60，看输出怎么变。**动手改比读十遍有用。**
3. **故意改错**：比如把 `>=` 改成 `>`、把 `[0]` 改成 `[1]`、把 `i < temps.Length` 改成 `i <= temps.Length`，看报什么错。
   —— 认识报错信息是零基础阶段最重要的技能之一。
4. **做每课末尾的练习题**，写完可以让我帮你看对不对。
5. 卡住就在这个会话里直接问我，把报错信息贴给我就行。

## 四、两个必须知道的坑（我已经帮你踩过了）

### 1. `.cs` 文件必须存成「UTF-8 带 BOM」

否则 C# 编译器会按系统默认编码（这台机器是 GBK）去读文件，**中文注释会变成乱码，严重时直接编译失败**。

- 用本仓库里的脚本自动补 BOM：
  ```powershell
  cd C:\Users\admin\Documents\deepseek-harness\default-workspace\csharp-learn
  powershell -ExecutionPolicy Bypass -File .\fix-bom.ps1
  ```
- **这个脚本本身是纯英文的，请不要往里加中文**（除非把脚本也存成 UTF-8 带 BOM）。
  原因很讽刺但很真实：脚本的第一版我在最后一行写了中文，结果这个"专门修编码问题的脚本"自己因为编码问题语法报错、根本跑不起来。
  **只要是脚本/代码文件，就都逃不过这条规则。**
- 以后用 Visual Studio 保存的文件默认就带 BOM，不用管。

### 2. 变量名和方法名建议用英文，注释用中文

```csharp
int speed = 1450;      // ✅ 推荐：英文名 + 中文注释
int 转速 = 1450;       // ⚠️ C# 允许，但不建议
```

理由：和 PLC 标签、电气图纸对照时英文名更通用；出错时搜索资料也更容易命中。
（不过**注释一定要写中文**，那是给你自己看的。）
